# 목록 db — `npm run test:db` 가 돌린다. 🔴 **진짜 DB 에 쓰는 시험들**이다.
#
# ── 먼저 읽을 것 ────────────────────────────────────────────────────────
# 이 목록을 돌리려면 시험 DB(dss_as_test)가 준비되어 있어야 하고, 그 준비는
# **A/S 저장소(RF_Service_System)에서** 한다 — 이 저장소는 마이그레이션을 갖지
# 않는다(설계서 E-2절). 순서는 docs/DB_TESTS.md 에 적어 두었다.
#
# ── 🔴 왜 목록을 unit 과 갈랐는가 ───────────────────────────────────────
# 이 사이트의 DATABASE_URL 은 A/S 와 **같은 dss_as** 이고 거기에는 실제 업무
# 자료가 들어 있다. 그래서 DB 에 붙는 시험은 unit 과 섞지 않는다:
#   - unit  : 부트스트랩 없음 → 환경변수도 DB 도 없다. DB 에 닿을 길이 없다.
#   - db    : 부트스트랩 있음 → DATABASE_URL 이 **시험 DB 로 바뀐 뒤** 시작한다.
#             바뀌지 않으면 src/lib/db/index.ts 의 관문이 접속을 막고 던진다.
#
# ── 플래그(package.json 의 "test:db") ───────────────────────────────────
#   --require ./scripts/node-windows-test-preload.cjs
#       Windows·Node 24 에서 tsx 가 uv_os_get_passwd ENOMEM 으로 넘어지는 것을
#       시험 도구 안에서만 우회한다. 남긴 이유: 이 PC 도 같은 Windows·Node 24 다.
#   --conditions=react-server
#       🔴 남긴 이유: 이 저장소의 mutation 들은 `import "server-only"` 로 시작한다
#       (src/lib/db/mutations/*.ts). 이 조건이 없으면 그 꾸러미가 "브라우저에서
#       불렀다"며 던져, 저장 코드를 부르는 시험이 아예 시작하지 못한다.
#   --import tsx
#       TypeScript 를 그대로 읽고 tsconfig 의 `@/*` · `@dss/*` 경로를 풀어 준다.
#       🔴 다음 --import 보다 **먼저** 와야 한다 — 부트스트랩도 .ts 파일이다.
#   --import ./scripts/test-db-bootstrap.ts
#       .env.local · .env.test.local 을 읽고, 안전장치를 통과한 TEST_DATABASE_URL
#       만 DATABASE_URL 자리에 놓고 DSS_DB_TEST_MODE=1 을 켠다.
#   --test --test-concurrency=1
#       🔴 시험 파일들이 **DB 한 벌을 함께 쓴다.** 동시에 돌면 서로의 줄을 보고
#       실패하거나, 더 나쁘게는 어쩌다 통과한다.
#
# A/S 의 test:db 와 같은 꼴이다. 뺀 것은 없다 — 넷 다 여기서도 쓸모가 있다.
#
# 적는 법은 unit.txt 머리를 볼 것.
