# ── 조각 3d-1b — 첨부의 「무엇을 받고, 어디에 두는가」 두 파일 ─────────────
# 위 3d-1a 머리말이 「아직 오지 않았다」고 적은 그 둘이다(A/S 의 같은 목록에서는
# 위 두 줄 사이에 끼어 있다). 사슬이 이어져야 해서 한 조각으로 함께 왔다:
# attachment-category ─(타입)→ attachment-allowlist ─(값 셋)→ attachment-path.
#
# 🔴 **`attachment-allowlist.ts` 는 통째로, `attachment-path.ts` 는 골라서** 왔다.
#    경로 파일에서 뺀 것은 이 사이트에 영영 안 생길 A/S 전용 일곱 함수(접수 건 넷 ·
#    제품 모델 셋, 약 165줄)이고, 그 일곱을 부르던 시험 열다섯도 함께 뺐다
#    (32개 → 13개). 무엇을 왜 뺐는지 · 뺀 시험이 지키던 값을 지금 무엇이 지키는지는
#    네 파일 머리말에 적어 두었다. 🔴 **잃은 규칙은 없다** — 남은 견적서 벌이 같은
#    규칙(`/` 뿐 · 소문자 · 상대경로 · UUID · 허용목록)을 글자 하나까지 똑같이 본다.
#
# 🔴 **접두어 상수 셋은 다 남겼다**(repair-cases · product-models · quotes). 이 사이트가
#    만들지 않는 두 접두어까지 남긴 까닭은 두 사이트가 **같은 `attachments` 표**를 보기
#    때문이다 — A/S 가 넣은 행을 읽다 `assertPortableStoredPath` 가 던지면 안 된다.
#    그것을 못 박는 것이 attachment-path.test.ts 의 「세 접두어를 모두 받는다」이고,
#    이 조각에서 가장 중요한 단언이다.
#
# 🔴 allowlist 시험에서는 **데모 계층을 보던 단언 넷**을 뺐다(이 사이트에는
#    `local/attachments/*` 가 없다 — 3d-1a 와 같은 까닭). 셋은 그 시험의 전부여서
#    `test()` 둘을 통째로 뺐다. 20MB 상한은 남은 두 자리가 여전히 못 박는다.
#
# 🔴 **DB 시험이 없다** — 두 파일 다 순수하다. attachment-path.ts 만 `node:path` 를
#    들여오지만 I/O 가 없어 `node --test` 에서 그대로 돈다. db.txt 에 아무것도 더하지
#    않았다. 🔴 다만 그 파일은 **클라이언트 묶음에 실을 수 없다** — 화면(`.tsx`)에서
#    들여오지 마라(그 파일 머리말).

# ── 조각 3d-2 — 「받기」: A/S 에서 붙인 엑셀을 PO 에서 내려받는다 ───────────
# 받기 통로(GET /api/quotes/{id}/xlsx)의 엑셀 전용 갈래가 **501 거절에서 파일 전송으로**
# 바뀌었다. 두 사이트가 같은 `attachments` 표와 같은 저장 루트(UPLOADS_DIR)를 보므로,
# 붙이는 칸이 없는 이 사이트에서도 A/S 에서 붙인 엑셀이 그대로 내려온다. 그래서
# `domain/quote-excel-only-download.ts`(3c-2 의 거절 문장)는 지워졌다.
#
# 🔴 **두 줄이 늘었다. 셋째 시험은 이미 이 목록에 있다**
#    (src/app/api/quotes/xlsx-route-source.test.ts — 위 3c-2 절).
#
# ① xlsx-download-source.test.ts — **A/S 에서 본문을 한 글자도 고치지 않고** 가져왔다.
#    고친 것은 `import` 한 줄뿐이다(`./download-source` →
#    `@/app/api/quotes/[id]/xlsx/download-source`).
#    🔴 **시험만 대괄호 밖에 둔다** — 원본(`download-source.ts`)은 라우트 곁,
#    `[id]` 폴더 안에 그대로 있다. `node --test` 가 경로를 글롭으로 읽어 `[id]` 를
#    「i 또는 d 한 글자」로 보기 때문이고(scripts/run-test-list.mjs 머리말), 이 목록에
#    대괄호 줄을 적으면 이제 **돌리기 전에 멈춘다**. 🔴 `import` 는 대괄호를 타도
#    멀쩡하다 — 그것이 3c-2 가 세운 본보기이고 여기서 그대로 따랐다.
#
# ② local-fs-adapter.test.ts — 🔴 **새로 썼다.** A/S 에는 이 파일의 단위 시험이 없다
#    (저쪽은 붙이기 · 내려받기 통합 시험이 덮고, 그 통합 시험은 붙이는 칸과 함께
#    3d-3 · 3d-4 에 온다). 재는 것은 **읽는 쪽 셋**이다 — 바이트 그대로 흘러나오는가 ·
#    저장 루트 밖을 가리키는 값을 막는가 · 없는 파일을 조용히 빈 것으로 주지 않는가.
#    그리고 `UPLOADS_DIR` 이 없을 때 **조용한 기본값으로 넘어가지 않고 던지는가**.
#    🔴 그 마지막 하나가 「설정이 빠진 채 한동안 잘 돌다가 배포 뒤에야 드러나는」 길을
#    막는 이 저장소의 유일한 장치다. 임시 폴더는 `after` 가 통째로 지운다.
#
# 🔴 **DB 시험이 없다** — 이 조각이 더한 조회(listLiveQuoteAttachments)는
#    `WHERE quote_id = ? AND is_deleted = false` 한 줄이고, 같은 표를 보는 목록 조회의
#    시험들이 이미 실제 DB 로 돌고 있다. db.txt 에 아무것도 더하지 않았다.
